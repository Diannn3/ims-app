# IMS Academic Hub — Product Context

## Product

IMS Academic Hub is a mobile-first student utility for the UPLB Institute of Mathematical Sciences Math Building. It connects indoor wayfinding, verified academic information, and private student tools through permanent room/space identifiers.

## Register

**Product surface.** This is primarily an application people use to finish tasks, not a marketing website. Prefer speed, clarity, density, predictability, accessibility, and trustworthy status communication over expressive landing-page spectacle.

## Primary audience

UPLB students who need to:

1. find a room or facility quickly;
2. navigate the Math Building with minimal cognitive load;
3. find verified academic information when it exists;
4. understand where to go for help;
5. use private student tools such as the local grade workspace.

Secondary users include faculty and IMS staff maintaining verified academic information and reviewing imports.

## Core jobs

- Search a room, course, person, service, or resource.
- Understand the result at a glance.
- Connect the result to its physical room when relevant.
- Start directions from a known building anchor.
- See clearly when institutional data is missing, stale, unverified, or unpublished.
- Maintain personal grade calculations without uploading student scores.
- Let staff stage, review, and publish institutional information through a fail-closed workflow.

## Primary aha moment

Search `MB 304` → immediately understand what/where it is → open the map → get directions.

The broader academic aha moment is:

Course/person/service → verified information → room → directions.

## Usage context

The app is often used while walking, between classes, one-handed on a phone, under time pressure, or with weak connectivity. Important actions must remain obvious at narrow widths and should not depend on hover, decorative motion, or perfect network conditions.

## Voice

- Calm
- Precise
- Academic without sounding bureaucratic
- Helpful without filler
- Honest about uncertainty
- Short, action-oriented interface copy

Use concrete status language such as `No verified current-term schedule loaded` rather than vague copy such as `Nothing here yet`.

## Product personality

**Academic Instrument.** The interface should feel like campus wayfinding + an academic timetable + a scientific instrument: clean, precise, quietly technical, and recognizably IMS.

## Trust rules

- Never fabricate current-semester courses, room assignments, faculty assignments, consultation schedules, or institutional notices.
- Never use a skeleton or decorative placeholder that implies institutional data exists when it does not.
- Distinguish navigation/static map data from live academic data.
- Expose verification/publication/freshness state where it changes user trust or action.
- Do not claim exact or accessibility-safe routing until the building has been physically verified.

## Anti-references

Avoid:

- generic SaaS dashboard aesthetics;
- giant marketing heroes on utility screens;
- purple/cyan AI gradients;
- glassmorphism as a default surface;
- nested cards and card grids used as layout substitutes;
- rounded-square icon tiles above every heading;
- decorative metric tiles without a user decision attached;
- excessive pills;
- oversized border radii;
- glow-heavy effects;
- bounce/elastic motion;
- hiding essential mobile functionality instead of adapting it;
- using all IMS brand colors decoratively on every screen;
- fake institutional content for visual completeness.

## Success criteria for the next milestone

Before real academic data is loaded, the app should already feel complete because navigation, search, room/service pages, grade tools, empty states, error states, and staff workflows all explain what works now and what data is intentionally absent.
